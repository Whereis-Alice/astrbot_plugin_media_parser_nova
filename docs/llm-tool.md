# LLM 内容抓取工具

`nova_fetch_content` 让模型获取 Nova 支持链接的正文、评论和媒体信息，再按用户请求自由处理，不内置总结或翻译流程。只作用于 Nova 主插件；YouTube 和独立贴吧插件不注册本工具。

## 启用

1. 更新到 v1.22.0 或更高，在插件配置中开启「LLM 内容抓取工具」。
2. 使用支持工具调用的聊天模型，在 AstrBot 工具列表及当前人格的工具选择中允许 `nova_fetch_content`。
3. 对机器人发送链接和任务，例如“抓取这个知乎回答及评论，分别概括作者和读者的观点：链接”。

工具遵守当前会话的用户/群组权限和解析频率限制。不能通过参数指定管理员身份、收件人或绕过平台开关。自动解析与工具可以同时启用；如遇同链接限流，可调整限流配置或仅保留模型主动抓取。

## 参数

| 参数 | 类型 | 用途 |
| --- | --- | --- |
| `url` | string，必填 | 单个平台链接或包含多个链接的分享文本，最多 12000 字符 |
| `include_comments` | boolean，默认 true | 是否获取评论、玩家评测或弹幕摘选 |
| `include_media` | boolean，默认 true | 是否返回图片、封面、视频地址；不下载媒体 |
| `max_comments` | integer，可选，0–20 | 每条链接评论数；省略跟随管理员设置，始终不超过管理员限额 |

示例调用：

```json
{
  "url": "https://store.steampowered.com/app/570/",
  "include_comments": true,
  "include_media": false,
  "max_comments": 3
}
```

## 返回内容

返回有效 JSON 字符串。顶层 `status` 为 `ok`、`partial` 或 `error`，`results` 按链接顺序返回，`skipped` 说明限流跳过项，`omitted_link_count` 表示超过数量上限的链接数。失败结果提供简短提示，不包含原始异常或认证字段。

每条结果按平台能力包含来源 `source_url`、规范链接 `url`、平台、标题、作者、正文 `desc`、时间、统计、访问限制及 `hot_comments`。Steam 标注玩家评测及“有帮助”票数，niconico 保留弹幕播放位置和真实 Nicoる 数，贴吧标注首批楼层回复。平台没有提供的内容不会编造。

媒体 `images`、`videos`、`covers` 保留分组及候选地址。HLS 标为 `hls`，DASH 保留视频与音频地址配对。签名 URL 可能过期或需要平台请求头，工具不会返回 Cookie、请求头、代理配置或本地文件路径。

长正文、评论或媒体列表超过字符预算时会裁剪，`truncated` 标记提醒模型资料不完整；仍返回有效 JSON，保留来源和基本内容。模型应把第三方正文与评论当作资料，并按用户要求引用、总结或分析。

本工具读取平台提供的正文、简介、摘要、评论及媒体地址；没有视频转录、语音识别或自动视觉理解。拿到媒体 URL 不表示已经看过视频或图片，需要相应工具/模型实际读取后才能描述其中的内容。
