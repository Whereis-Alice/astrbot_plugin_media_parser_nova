# 卡片渲染

开启「消息输出 → 卡片渲染」后，插件会先生成一张解析卡片，再按「卡片模式」决定是否继续发送普通文本。卡片渲染失败时自动回退为文本，视觉功能不会阻断媒体解析。

## 卡片模式

`卡片模式` 是卡片与普通文本发送关系的唯一控制项：

| 模式 | 实际发送行为 |
| --- | --- |
| 卡片+文本同条发送 | 卡片图片与第一段普通文本放入同一个 AstrBot 消息链，例如 `[Image, Plain]`；超过单条长度上限的后续文本分片继续单独发送 |
| 卡片+文本分开发 | 卡片先单独发送，普通文本按分片分别发送 |
| 仅卡片 | 发送卡片，并把原始链接放在同一消息链中；不发送标题、作者、正文或独立热评文本 |

图片、视频等富媒体仍会按平台组件能力和体积限制继续发送。翻译配置不改变上述发送关系，只决定卡片或普通文本使用原文还是译文，见 [配置说明 → 翻译](configuration.md#翻译)。

## 三轴：皮肤 × 深浅 × 布局

卡片视觉由三个互相独立的维度决定，任意组合都会真实生效，共 8 × 2 × 4 = **64 种版式**：

| 维度 | 配置项 | 取值 |
| --- | --- | --- |
| 皮肤 | 卡片风格 | 极光 / 报章 / 测控 / 展陈 / 夜曲 / 哔哩哔哩 / X（推特） / YouTube / 跟随平台 |
| 配色 | 深浅配色 | 深色 / 浅色（每套皮肤都有专属的两版配色，不是简单反色） |
| 布局 | 版式布局 | 标准 / 杂志 / 沉浸式 / 信息流 |

皮肤决定画布气质：背景与装饰、面板形态、区块顺序、字体搭配与排版策略。布局只决定区块的空间组织方式。因此「报章 + 浅色 + 杂志」和「报章 + 深色 + 信息流」是两张结构不同的卡片，而不是同一张图换色。

## 皮肤跟随平台

「卡片风格」里还有一个特殊取值 **跟随平台**：选它之后，插件按链接所属平台自动挑仿站皮肤——B 站链接用哔哩哔哩皮肤，X / Twitter 用 X 皮肤，YouTube 用 YouTube 皮肤，其余尚未收录的平台回落极光。想让每张卡片都像它来的那个站，选这一项就够了。

反过来，只要明确选了某套皮肤，插件就绝不会擅自替换：抖音链接配「报章」也照样是报章。自动挑选只在「跟随平台」这一个取值下发生。

![皮肤跟随平台](card-skins/platform-skin.png)

> 「跟随平台」下，从左到右分别是 B 站、YouTube、X 的链接——三张卡片的配色、字重、圆角与家具都不一样。

## 卡片家具跟随平台

皮肤只负责基调——配色、字重、圆角、留白、区块顺序。页签条文案、底部操作栏的动作集与画法、评论输入框的占位文字这些「界面家具」按链接所属平台换件，所以同一套皮肤在不同平台下不会出现张冠李戴的违和感。

| 平台 | 页签条 | 操作栏 | 输入框占位 |
| --- | --- | --- | --- |
| B 站 / 微博 / 小红书 / 小黑盒 / NGA / 头条 / 闲鱼 / AcFun | 评论 N ・ 赞和转发 M（点赞+转发之和） | 图标在上、数字在下的四组：转发 / 评论 / 收藏 / 点赞 | 点我发评论 |
| YouTube | 只有「评论 N」 | 圆角药丸：👍 赞数 / 👎 / 分享 / 保存 | 添加评论… |
| Twitter / X | 不画页签，只留一条发丝分隔线 | 等距铺满内容宽度的五枚：回复 / 转推 / 喜欢（粉色实心心形）/ 书签 / 分享 | 发布你的回复 |
| 抖音 / 快手 / TikTok | 评论 N ・ 赞和转发 M | 同 B 站 | 说点什么… |
| Pixiv | 评论 N | 图标数字同行：评论 / 分享 / 收藏 | 留下评论… |

页签条里的次级项在平台没有这个概念、或者数值取不到时会整枚隐藏，而不是留一个光标签。

X 的换件还多几处：时间行改成「时间 · N 查看」的原生语序（而不是把浏览量塞进页签），封面上不压播放量角标，每条回复正文下方追加一行 回复 / 转推 / 喜欢 的迷你图标。

家具自带的品牌色不受皮肤影响：X 的实心喜欢永远是 X 粉、认证角标永远是 X 蓝勾，YouTube 的认证角标是原版的灰底白勾，中文社交那枚蓝色闪电角标才跟着皮肤的辅助强调色走。所以「哔哩哔哩皮肤 + X 链接」不会把粉心画成 B 站蓝。

![卡片家具跟随平台](card-skins/platform-chrome.png)

> 同一套「哔哩哔哩」皮肤 + 信息流布局 + 深色配色，从左到右分别是 B 站、YouTube、X 的链接。

## 排版行为

卡片先测量所有区块的真实高度再绘制，没有硬编码的区块高度：空的正文、引用、统计或评论区会完全消失，不留空白面板。卡片宽度可在 520-1080 像素之间调整，字号、间距与圆角按宽度整体缩放。

文字默认使用仓库内置字体，不依赖宿主系统装了哪些中文字体；「自定义字体路径」留空即用内置字体，填写时支持 `.ttf` / `.otf` / `.ttc`，路径无效会退回自动探测并打一条 WARNING。

媒体按真实宽高比自适应排布。两张图片获得相近的展示面积；更多图片时行内张数自动均衡（例如 5 张排成 2+3、7 张排成 2+2+3），末行不会留下空洞，也不会把某张图压成细条。超出当前版式容量时，最后一格标出 `+N`。只有主视觉格子会使用毛玻璃衬底补足画幅，网格缩略图统一裁切填满。

卡片链接保留完整的协议、路径、查询参数和片段，超长链接按字符换行（最多 3 行），页脚底板随行数自动变高，不会为了宽度删除 `https://` 或直接截断。仿站皮肤（哔哩哔哩 / X / YouTube）例外：它们把去掉协议前缀的链接与署名合并成一行浅灰小字放到顶栏右上角，底部让给原版操作栏。

作者头像优先使用平台提供的图片，失败时回退首字母占位；长作者名与作者 ID 在各自区域内换行。所有文字颜色都经过对比度校正，图标全部由几何绘制，不依赖系统 emoji 字体。

Twitter/X 普通推文没有独立标题时，插件不会生成「作者名(@ID) 的推文」这类重复占位标题，正文直接作为主内容绘制一次。

平台没有提供封面或封面下载失败时，插件使用仓库内置的原创无文字 Nova 抽象纹理，不会把固定角色或无关文案带进公开卡片。

配置里若写着 `Nova 原生` / `编辑室` / `信号终端` / `海报档案` / `霓虹夜景` / `B站动态` / `推特卡片` / `油管卡片` 这类别名，会自动映射到极光 / 报章 / 测控 / 展陈 / 夜曲 / 哔哩哔哩 / X / YouTube，无需手动修改。

## 署名与原链接

「卡片署名文案」默认为 `Nova解析`，可改成 `Alice解析` 等文字，最多 32 个字符。修改署名会自动使用新的卡片缓存键，不会复用旧署名图片。

另有两个开关，八套皮肤、四种布局全部生效：

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| 显示卡片署名 | 开 | 关闭后卡片不再绘制署名文案 |
| 显示原文链接 | 开 | 关闭后卡片不再绘制来源链接（普通文本里的链接不受影响） |

两个开关都参与卡片缓存键，关掉后立刻生效，不会命中旧图。

## 热评合并到卡片

要把热评放进卡片，需要同时满足：

1. 在「消息输出 → 附加内容：热评」中把「热评条数」设为大于 `0`，并开启对应平台。
2. 在「消息输出 → 卡片渲染」中开启「热评合并到卡片」。

卡片最多展示前 5 条热评，保留评论作者、ID、点赞数和时间。评论头像也会一并下载并绘制成圆形头像，八套皮肤都生效；B 站、微博、小红书、Twitter/X、小黑盒都会带回真实头像。平台没有返回头像时使用中性灰的圆形占位（首字母，或昵称是纯 emoji 时用剪影），不使用品牌色块。评论区使用当前皮肤自己的视觉结构追加到同一张 PNG。

「卡片单条热评字数上限」控制单条评论占用的卡片高度，范围 `60-600`，默认 `180`。只有评论超过上限时才追加省略号；保留下来的内容按卡片宽度完整换行。希望评论更完整时提高上限，希望卡片更紧凑时降低上限。

要让热评只出现在卡片、同时仍保留标题和正文文本，再关闭「附加内容：热评 → 在普通文本中显示热评」。这个开关只控制普通文本里的热评段落，不改变 `卡片模式`：

- 卡片模式可以继续选「卡片+文本同条发送」或「卡片+文本分开发」，正文照常发送，热评只进卡片。
- 选择「仅卡片」会隐藏全部普通文本，只保留卡片、原始链接和富媒体。
- 同时关闭「热评合并到卡片」和「在普通文本中显示热评」时，插件仍按平台配置获取热评，并在启用翻译时参与翻译，但聊天中不展示热评。

## 重新生成文档截图

```bash
python tools/render_skin_docs.py
```
