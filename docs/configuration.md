# 配置说明

插件默认开启各平台的「全部发送」，安装后直接发链接即可。本文按配置页分组说明常用项。平台专项配置见 [平台说明](platforms.md)，卡片相关配置见 [卡片渲染](cards.md)。YouTube 已迁移到独立插件 [YouTube Nova](https://github.com/Whereis-Alice/astrbot_plugin_youtube_nova)。

## 解析器与输出模式

每个平台可以单独选择：

- **关闭**：不提取、不解析该平台链接
- **全部发送**：发送文本摘要和图片/视频
- **仅文本**：只发送标题、作者、正文等摘要，不下载媒体
- **仅富媒体**：只发送图片/视频，不发送文本摘要

## 触发方式

- **自动解析链接**：消息中出现支持的链接时自动处理
- **回复触发解析**：引用包含链接的消息，再发送配置关键词
- **手动触发关键词**：关闭自动解析时使用。默认包含 `视频解析`、`解析视频` 和更通用的 `媒体解析`

## 文本字段

在「消息输出 → 文本元数据」中可以分别控制标题、作者、发布时间、原始链接和正文是否展示。关闭字段只影响消息展示，同时也会减少提交给翻译模型的内容。

## 消息聚合

- **不聚合**：逐条发送
- **全部聚合**：尽量使用合并转发，超大视频仍可能单独发送
- **按条件聚合**：图片、视频或节点数量达到阈值时才聚合

## 视频体积与发送上限

「下载设置」里的体积相关配置分别管**下载**、**发送**、**压缩**和**聚合**：

| 配置项 | 默认值 | 作用 |
| --- | --- | --- |
| 视频大小上限（`max_video_size_mb`） | 1000 MB | 下载上限，也是硬上限。普通视频先预检 `Content-Length`，DASH/M3U8 按下载完成后的实际体积兜底；填 0 不限制 |
| 可发送视频体积上限（`send_video_max_mb`） | 48 MiB | **聊天平台能收下的单条视频预算**。超过预算时按下面的顺序压缩或降级；填 0 不限制 |
| 超限自动压缩（`transcode_oversize_video`） | 开启 | 超过可发送上限时先用 ffmpeg 压到上限以内再发，压不下来才退回「信息 + 封面」 |
| 压缩超时（`transcode_timeout_seconds`） | 600 秒 | 单个视频的压缩时间上限，可填 30–3600；超时按压缩失败处理 |
| 大视频阈值（`large_video_threshold_mb`） | 100 MB | 超过阈值的视频单独发送，不放进合并转发；有效上限 100 MB，填 0 不限制 |

`send_video_max_mb` 单独存在的原因是**下载得到不等于发得出去**。LLOneBot 8.1.9 的 QQ 富媒体（Highway）视频通道实测要求文件严格小于 53 MiB，达到 53 MiB 会返回 `102902` 或 `101`；默认 48 MiB 为封装与码率波动留出余量。其他协议端可按实测值调整。插件的处理顺序是：

1. **超过硬上限不下载**：预估或实际体积超过 `max_video_size_mb` 时直接跳过视频，改发「信息 + 封面」。
2. **超过可发送预算先压缩**：开启自动压缩时，下载阶段只受硬上限约束；拿到文件后若超过 `send_video_max_mb`，按时长反推码率预算，必要时降分辨率并锁 30fps，用 libx264 + AAC 重编码到预算以内。产物跟随原有缓存清理。
3. **压不下来才降级**：没装 ffmpeg、视频太长、超时或压缩后仍然超限时，退回「信息 + 封面」，并在消息里写清原因。关掉自动压缩则超限即跳过。
4. **发送失败会说话**：部分内容发送失败时，除了后台 WARNING，还会在会话里补一条简短提示，并附原始链接。

不同协议端的实际上限差别不小，可按自己的部署实测值调整；把上限调大只影响插件是否愿意尝试，平台该拒还是会拒。压缩是 CPU 密集操作，多个视频会串行处理；机器较弱又常遇大视频时，可以调低 `send_video_max_mb` 之外再把压缩超时收紧，或直接关掉自动压缩。

## 翻译

翻译完成后，插件把标题、正文和已获取热评的译文合并到展示副本中，不会额外发送一条独立的「翻译结果」消息。

「译文应用范围」只决定哪些展示内容使用译文：

- **仅卡片使用译文**：卡片显示译文，普通文本仍显示原文。需要开启卡片渲染才能看到效果。
- **卡片和文本均使用译文**：卡片和普通文本都显示译文，但普通文本是否发送、是否与卡片同条发送，仍由 `卡片模式` 决定。

「翻译内容」控制标题是否参与翻译：「仅正文」只翻译正文和热评，「正文和标题」时标题也会翻译。解析结果中已获取到热评时，热评正文会和主内容一起进入翻译流程。

常见组合：

| 卡片模式 | 译文应用范围 | 结果 |
| --- | --- | --- |
| 卡片+文本同条发送 | 仅卡片使用译文 | 同一消息链中，卡片显示译文，普通文本保留原文 |
| 卡片+文本同条发送 | 卡片和文本均使用译文 | 同一消息链中，卡片与普通文本都显示译文 |
| 仅卡片 | 任一范围 | 只发送卡片和原始链接，不额外发送普通文本或翻译文本 |

翻译失败或模型配置不可用时，插件继续使用原文渲染和发送，不影响图片、视频或 ZIP 归档。

## 缓存目录

建议为插件配置可写的缓存目录。缓存目录可用时，插件可以先下载媒体再发送，能够携带必要的 Referer、Cookie 和请求头，通常比直接发送远程 URL 更稳定。

以下能力通常需要缓存目录：图片下载与发送、B 站 Cookie 解锁后的 DASH 音视频合并、微博视频下载、小黑盒视频与 M3U8、Twitter/X 视频缓存、Pixiv 图片缓存。

非 Docker 环境下，插件优先使用 AstrBot 数据目录中的：

```text
plugin_data/astrbot_plugin_media_parser_nova/cache
```

Docker 环境请确保该目录对 AstrBot 和协议端的权限、挂载关系符合部署方式。

## 代理

TikTok、Twitter/X、Pixiv、小黑盒等平台可能受到地区或网络限制。可以在「代理设置」中填写 HTTP 或 SOCKS5 代理，并按平台开启解析或媒体下载代理。

## ffmpeg

以下功能可能需要系统安装 `ffmpeg`：

- DASH 音视频合并（B 站高画质）
- M3U8 封装
- 视频仅发送封面时截取首帧
- 超过可发送上限的视频自动压缩（同时用到 `ffprobe`）

没有 ffmpeg 时，插件仍会尽量使用原始封面或普通直链路径；无法完成的媒体会在摘要中说明原因。

## ZIP 归档

可在「消息输出 → 导出行为 → ZIP 归档」中设置归档命令。使用方式：

1. 引用一条包含可解析链接的消息。
2. 发送只包含归档命令的消息。
3. 插件生成 ZIP，并写入解析摘要、结构化详情和已成功下载的媒体。

归档根目录为 `media_parser_nova/`，不会与原插件的归档目录混用。归档总大小可配置，无法下载的媒体会在 `metadata.txt` 中保留原链接和失败原因。

## 限制与清理

- 解析频率限制可以按链接和用户分别配置
- 缓存目录按配置的保留时长与总量自动清理
- 第三方返回的媒体地址只允许公网，避免误访问本地或内网地址
