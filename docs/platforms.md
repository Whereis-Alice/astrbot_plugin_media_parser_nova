# 平台专项说明

各平台通用的输出模式、聚合、体积上限等设置见 [配置说明](configuration.md)。本文只收录需要额外配置或有平台特殊行为的部分。YouTube 已迁移到独立插件 [YouTube Nova](https://github.com/Whereis-Alice/astrbot_plugin_youtube_nova)。

## B 站

在「B 站增强」中开启 Cookie 解析并填写浏览器请求中的 Cookie，可以解锁账号允许的更高画质。Cookie 失效后，可以开启「管理员协助登录」，管理员私聊机器人发送 `B站更新Cookie`（可在面板改名），由插件私聊管理员回发二维码完成扫码更新。

建议：

- 不要把 Cookie 写入公开仓库、截图或聊天记录
- 管理员 ID 只填写可信账号
- Cookie 失效时先确认缓存目录和 ffmpeg 可用

`b23.tv` 短链会先展开成完整地址再解析。链接提取只取短链里的字母数字 slug，紧跟在后面的中文（例如 `https://b23.tv/XXXXXXX媒体解析`）不会被当成链接的一部分。

## Twitter/X

正文解析优先使用 FxTwitter 接口，服务不可用时回退到 Guest GraphQL。图片和视频 CDN 可能需要代理或缓存下载。

X 链接提取会保留消息中的出现顺序，视频候选项带容错处理；作者头像缺失时也不会阻断整条推文的解析。

### 热评与互动统计需要 Nitter

X 已经停止对未登录访问输出带回复数据的服务端渲染页面：用爬虫 UA 请求帖子页要么直接返回 403，要么返回 200 但页面里既没有 `application/ld+json` 也没有 `Comment` 节点。换 UA、换 `/i/status/` 路径都绕不过去，所以**默认配置下 Twitter/X 抓不到热评是平台行为，不是插件故障**。

想要热评和互动数字，请在「消息输出 → 附加内容：热评 → Twitter/X 的 Nitter 实例地址」填入一个可用的 [Nitter](https://github.com/zedeus/nitter) 地址。Nitter 是 X 的开源前端，未登录即可读到回复区与统计数字。

```text
http://127.0.0.1:8585
```

- 支持逗号 / 分号 / 空格分隔多个实例，插件按顺序尝试，前一个失败自动换下一个
- 缺少协议时按 `http://` 补全；末尾斜杠可有可无
- 指向 `localhost`、`127.x`、`10.x`、`192.168.x`、`172.16~31.x` 的自建实例一律直连，不会被「解析走代理」的设置带去绕代理，也不会被媒体下载的公网地址防护拦下（Nitter 地址由你自己填写，属于显式信任；第三方返回的媒体地址仍然只允许公网）
- 单个实例 10 秒超时、整体 18 秒预算，超时即放弃剩余实例，不会拖慢正文解析
- 公共 Nitter 实例普遍不稳定，长期使用建议自建

配置好之后可以额外获得：

- 回复区热评（按点赞数排序，带作者、头像、时间、点赞数）
- 卡片底部的喜欢 / 转发 / 评论 / 阅读统计
- FxTwitter 与 GraphQL 都拿不到作者头像时的头像兜底（自动升级到 `_400x400` 清晰度）

Nitter 抓取成功后就不会再去试 X 公开页（那条路线已经不返回回复数据，白等只会拖慢解析）。只有 Nitter 全部失败或未配置时才回落到 X 公开页，并在失败后按 1 小时冷却给一条 INFO 引导；正文、图片、视频解析不受任何影响。

## 小黑盒

热评只用于能够稳定返回评论结构的 BBS/link 帖子。插件调用 BBS 接口获取首批楼层并整理为统一热评字段，也支持只有正文、没有图片或视频的 BBS 帖子。

游戏详情、商店详情等页面不会强行附加热评；如果平台接口没有可靠评论数据，插件宁可不显示，也不会从无关字段拼接或伪造评论。

## 其他平台

### niconico

支持 `www.nicovideo.jp/watch/sm...`、`nm...`、`so...`、数字视频 ID 和 `nico.ms` 视频短链。先请求官方 watch API，再申请 Domand HLS 播放权限；封面、简介与作者可独立展示。公开内容可匿名访问，登录内容可填写 `niconico.cookie`（含 `user_session`），但仍受会员、地区、版权和账号权限限制。媒体下载支持标准 AES-128 HLS，合并需要 ffmpeg；SAMPLE-AES 等 DRM 内容不支持。

### Steam

支持 `store.steampowered.com/app/<appid>` 游戏商店页，使用官方 `appdetails` API 获取介绍、发行信息、价格、封面、截图与宣传视频。当前 Steam 宣传视频已迁移到 HLS，兼容旧 MP4/WebM 字段。默认最多 6 张截图和 1 条宣传视频，可分别设为 0 关闭。`steam.language` 和 `steam.country_code` 控制语言及地区；下架或在指定地区不可用的游戏会明确提示。

### 微博、TikTok 和知乎

微博支持桌面帖子、`m.weibo.cn/detail/...`、`m.weibo.cn/status/...`、视频页面和 `t.cn` 短链。访客 Cookie 失败不会阻断后续公共接口；无媒体的纯文字帖子也可返回。匿名接口被登录页或风控页替换时会提示填写 `weibo.cookie`。

TikTok 支持标准视频、图集和 `vm`/`vt`/`/t/` 分享短链，提供页面 JSON 与 curl 回退。可配置 `tiktok.cookie` 和代理；登录、地区或风控限制不会被当作成功解析。curl 回退有总耗时预算。

知乎支持问题、回答和 `zhuanlan.zhihu.com/p/...` 文章，按公开 API、页面初始数据和 JSON-LD 回退，提取作者、正文和图片，存在公开视频地址时一并返回。可填写 `zhihu.cookie`。匿名 403、登录验证、付费和删除内容会提示受限；页面只有摘要时会说明，不将摘要标记为全文。

以上平台在「解析器与输出模式」中独立启停；对应代理开关需要先填写代理地址。抖音、快手、小红书、闲鱼、今日头条、Pixiv 等既有平台的取数思路、接口选择和已知坑位见 [各平台解析思路备忘](PARSER_METHOD_MEMO.md)。
