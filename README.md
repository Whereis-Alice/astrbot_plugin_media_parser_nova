# Nova 流媒体解析

`astrbot_plugin_media_parser_nova` 是一个面向 AstrBot 的多平台媒体解析插件。它会自动识别消息中的平台链接，提取标题、作者、正文、图片和视频，并按配置发送文本摘要或媒体内容。

项目地址：[Whereis-Alice/astrbot_plugin_media_parser_nova](https://github.com/Whereis-Alice/astrbot_plugin_media_parser_nova)

本项目是一个**独立命名的维护版本**：插件 ID、Python 内部包名、日志名、缓存标记和 ZIP 归档目录均使用 Nova 专属标识，因此不会覆盖原插件的配置和缓存。插件功能基于上游公开源码继续维护，并在此基础上修复问题和补充防御性处理。

> 注意：虽然两个插件可以安装在同一个 AstrBot 中，但如果两者都开启自动解析，同一条链接可能会被回复两次。建议只启用一个插件的自动解析功能。

## 功能概览

- 自动提取消息、回复消息和部分 QQ/平台卡片中的链接
- 支持视频、图片、纯文本和部分平台热评
- 每个平台独立设置为：关闭、全部发送、仅文本、仅富媒体
- 支持不聚合、全部聚合、按条件聚合三种消息发送方式
- 支持卡片渲染，6 套皮肤 × 深浅配色 × 4 种布局共 48 种版式，并自动编排多图
- 支持标题、正文和热评翻译；译文可以只用于卡片，也可以同时用于普通文本
- 支持把已获取的热评直接合并到同一张卡片中
- 支持 B 站 Cookie、高画质解析和管理员协助扫码更新
- 支持媒体缓存、媒体中转和 ZIP 归档
- 对下载大小、解析频率、缓存清理和公网 URL 做了限制与兜底

## 安装

### WebUI 安装

插件发布到市场后，在 AstrBot WebUI 中搜索：

```text
astrbot_plugin_media_parser_nova
```

### 手动安装

1. 将本项目目录放入 AstrBot 的插件目录。
2. 确认目录名为 `astrbot_plugin_media_parser_nova`。
3. 安装 `requirements.txt` 中的依赖，或让 AstrBot 在加载插件时自动安装。
4. 重启 AstrBot，在插件配置页完成设置。

依赖包括 `aiohttp`、`cryptography`、`qrcode[pil]` 和 `pillow`。Python 版本建议为 3.10 或更高，AstrBot 版本要求为 4.25 或更高。

## 基础配置

插件默认开启各平台的“全部发送”，安装后即可尝试发送链接。常用配置如下：

### 解析器与输出模式

每个平台可以单独选择：

- **关闭**：不提取、不解析该平台链接
- **全部发送**：发送文本摘要和图片/视频
- **仅文本**：只发送标题、作者、正文等摘要，不下载媒体
- **仅富媒体**：只发送图片/视频，不发送文本摘要

### 触发方式

- **自动解析链接**：消息中出现支持的链接时自动处理
- **回复触发解析**：引用包含链接的消息，再发送配置关键词
- **手动触发关键词**：关闭自动解析时使用。默认包含 `视频解析`、`解析视频` 和更通用的 `媒体解析`

### 文本字段

在“消息输出 → 文本元数据”中，可以分别控制标题、作者、发布时间、原始链接和正文是否展示。关闭字段只影响消息展示，也会同步减少提交给翻译模型的内容。

### 消息聚合

- **不聚合**：逐条发送
- **全部聚合**：尽量使用合并转发，超大视频仍可能单独发送
- **按条件聚合**：图片、视频或节点数量达到阈值时才聚合

## 卡片渲染

开启“消息输出 → 卡片渲染”后，插件会先生成一张解析卡片，再按“卡片模式”决定是否继续发送普通文本。卡片渲染失败时会自动回退为文本，不会因为视觉功能阻断媒体解析。

### 卡片模式

`卡片模式` 是卡片与普通文本发送关系的唯一控制项：

| 模式 | 实际发送行为 |
| --- | --- |
| 卡片+文本同条发送 | 卡片图片与第一段普通文本放入同一个 AstrBot 消息链，例如 `[Image, Plain]`；超过单条长度上限的后续文本分片会继续单独发送 |
| 卡片+文本分开发 | 卡片先单独发送，普通文本按分片分别发送 |
| 仅卡片 | 发送卡片，并把原始链接放在同一消息链中；不再发送标题、作者、正文或独立热评文本 |

图片、视频等富媒体仍会根据平台组件能力和大小限制继续发送。翻译配置不会改变上述发送关系，只负责决定卡片或普通文本使用原文还是译文。

### 卡片三轴：皮肤 × 深浅 × 布局

卡片视觉由三个互相独立的维度决定，任意组合都会真实生效，共 6 × 2 × 4 = **48 种版式**：

| 维度 | 配置项 | 取值 |
| --- | --- | --- |
| 皮肤 | 卡片风格 | 极光 / 报章 / 测控 / 展陈 / 夜曲 / 哔哩哔哩 |
| 配色 | 深浅配色 | 深色 / 浅色（每套皮肤都有专属的两版配色，不是简单反色） |
| 布局 | 版式布局 | 标准 / 杂志 / 沉浸式 / 信息流 |

皮肤决定画布气质：背景与装饰、面板形态、区块顺序、字体搭配与排版策略。布局只决定区块的空间组织方式。因此“报章 + 浅色 + 杂志”和“报章 + 深色 + 信息流”是两张结构不同的卡片，而不是同一张图换色。

#### 排版行为

卡片先测量所有区块的真实高度再绘制，没有硬编码的区块高度：空的正文、引用、统计或评论区会完全消失，不留空白面板。卡片宽度可在 520-1080 像素之间调整，字号、间距与圆角会按宽度整体缩放。

媒体按真实宽高比自适应排布。两张图片获得相近的展示面积；更多图片时行内张数会自动均衡（例如 5 张排成 2+3、7 张排成 2+2+3），末行不会留下空洞，也不会把某张图压成细条。超出当前版式容量时，最后一格标出 `+N`。只有主视觉格子会使用毛玻璃衬底补足画幅，网格缩略图统一裁切填满。

卡片链接保留完整的协议、路径、查询参数和片段，超长链接按字符换行（最多 3 行），页脚底板会随行数自动变高，不会为了宽度删除 `https://` 或直接截断。哔哩哔哩皮肤例外：它把去掉协议前缀的链接与署名合并成一行浅灰小字放到顶栏右上角，底部让给原版操作栏。

作者头像优先使用平台提供的图片，失败时回退首字母占位；长作者名与作者 ID 会在各自区域内换行。所有文字颜色都经过对比度校正，图标全部由几何绘制，不依赖系统 emoji 字体。

Twitter/X 普通推文没有独立标题时，插件不会生成“作者名(@ID) 的推文”这类重复占位标题，正文直接作为主内容绘制一次。

旧配置中的皮肤名（Nova 原生 / 编辑室 / 信号终端 / 海报档案 / 霓虹夜景 / B站动态）会自动迁移为极光 / 报章 / 测控 / 展陈 / 夜曲 / 哔哩哔哩，无需手动修改。

当平台没有提供封面或封面下载失败时，插件使用仓库内置的原创无文字 Nova 抽象纹理，不会把固定角色或无关文案带进公开卡片。

### 署名与原链接

“卡片署名文案”默认为 `Nova解析`，可改成 `Alice解析` 等文字，最多 32 个字符。修改署名会自动使用新的卡片缓存键，不会复用旧署名图片。

另有两个开关，六套皮肤、四种布局全部生效：

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| 显示卡片署名 | 开 | 关闭后卡片不再绘制署名文案 |
| 显示原文链接 | 开 | 关闭后卡片不再绘制来源链接（普通文本里的链接不受影响） |

两个开关都参与卡片缓存键，关掉后立刻生效，不会命中旧图。

### 热评合并到卡片

要把热评放进卡片，需要同时满足：

1. 在“消息输出 → 附加内容：热评”中把“热评条数”设为大于 `0`，并开启对应平台。
2. 在“消息输出 → 卡片渲染”中开启“热评合并到卡片”。

卡片最多展示前 5 条热评，并保留评论作者、ID、点赞数和时间。评论头像也会一并下载并绘制成圆形头像，六套皮肤都生效；B 站、微博、小红书、Twitter/X、小黑盒都会带回真实头像。平台没有返回头像时使用中性灰的圆形占位（首字母，或昵称是纯 emoji 时用剪影），不使用品牌色块。评论区会使用当前皮肤自己的视觉结构追加到同一张 PNG，不会把某套皮肤的评论面板套到另一套皮肤上。

“卡片单条热评字数上限”用于控制单条评论占用的卡片高度，范围为 `60-600`，默认 `180`。插件只会在评论超过上限时追加省略号；保留下来的内容会按卡片宽度完整换行，不再使用固定三行硬裁切。希望评论更完整时可以提高上限，希望卡片更紧凑时可以降低上限。

要让热评只出现在卡片、同时仍保留标题和正文文本，再关闭“附加内容：热评 → 在普通文本中显示热评”。这个开关只控制普通文本里的热评段落，不改变 `卡片模式`：

- 卡片模式可以继续选“卡片+文本同条发送”或“卡片+文本分开发”，正文照常发送，热评只进卡片。
- 选择“仅卡片”会隐藏全部普通文本，只保留卡片、原始链接和富媒体。
- 如果同时关闭“热评合并到卡片”和“在普通文本中显示热评”，插件仍会按平台配置获取热评，并在启用翻译时参与翻译，但聊天中不会展示热评。

## 翻译与卡片

翻译完成后，插件会把标题、正文和已获取热评的译文合并到展示副本中。翻译不会再额外发送一条独立的“翻译结果”消息。

配置页中的“译文应用范围”只决定哪些展示内容使用译文：

- **仅卡片使用译文**：卡片显示译文，普通文本仍显示原文。需要开启卡片渲染才能看到译文效果。
- **卡片和文本均使用译文**：卡片和普通文本都直接显示译文，但普通文本是否发送、是否与卡片同条发送，仍完全由 `卡片模式` 决定。

“翻译内容”控制标题是否参与翻译：选择“仅正文”时只翻译正文和热评；选择“正文和标题”时标题也会翻译。只要解析结果中已经获取到热评，热评正文会和主内容一起进入翻译流程。

常见组合示例：

| 卡片模式 | 译文应用范围 | 结果 |
| --- | --- | --- |
| 卡片+文本同条发送 | 仅卡片使用译文 | 同一消息链中，卡片显示译文，普通文本保留原文 |
| 卡片+文本同条发送 | 卡片和文本均使用译文 | 同一消息链中，卡片与普通文本都显示译文 |
| 仅卡片 | 任一范围 | 只发送卡片和原始链接；不会额外发送普通文本或翻译文本 |

如果翻译失败或模型配置不可用，插件会继续使用原文渲染和发送，不影响图片、视频或 ZIP 归档。

## 缓存、代理与 ffmpeg

### 缓存目录

建议为插件配置可写的缓存目录。缓存目录可用时，插件可以先下载媒体再发送，能够携带必要的 Referer、Cookie 和请求头，通常比直接发送远程 URL 更稳定。

以下能力通常需要缓存目录：

- 图片下载和发送
- B 站 Cookie 解锁后的 DASH 音视频合并
- 微博视频下载
- 小黑盒视频、BBS 媒体和 M3U8
- Twitter/X 视频缓存
- Pixiv 图片缓存

非 Docker 环境下，插件优先使用 AstrBot 数据目录中的：

```text
plugin_data/astrbot_plugin_media_parser_nova/cache
```

Docker 环境请确保该目录对 AstrBot 和协议端的权限、挂载关系符合部署方式。

### 代理

TikTok、Twitter/X、Pixiv、小黑盒等平台可能受到地区或网络限制。可以在“代理设置”中填写 HTTP 或 SOCKS5 代理，并按平台开启解析或媒体下载代理。

### ffmpeg

以下功能可能需要系统安装 `ffmpeg`：

- DASH 音视频合并
- M3U8 封装
- 视频仅发送封面时截取首帧

没有 ffmpeg 时，插件仍会尽量使用原始封面或普通直链路径；无法完成的媒体会在摘要中说明原因。

## B 站 Cookie

在“B 站增强”中开启 Cookie 解析并填写浏览器请求中的 Cookie，可以解锁账号允许的更高画质。Cookie 失效后，可以开启“管理员协助登录”，由插件私聊管理员完成扫码更新。

建议：

- 不要把 Cookie 写入公开仓库、截图或聊天记录
- 管理员 ID 只填写可信账号
- Cookie 失效时先确认缓存目录和 ffmpeg 可用

## Twitter/X 说明

Twitter/X 默认优先使用 FxTwitter 接口，服务不可用时回退到 Guest GraphQL。图片和视频 CDN 可能需要代理或缓存下载。

X 链接提取会保留消息中的出现顺序，视频候选项带容错处理；作者头像缺失时也不会阻断整条推文的解析。

### 热评与互动统计需要 Nitter

X 已经停止对未登录访问输出带回复数据的服务端渲染页面：用爬虫 UA 请求帖子页要么直接返回 403，要么返回 200 但页面里既没有 `application/ld+json` 也没有 `Comment` 节点。换 UA、换 `/i/status/` 路径都绕不过去，所以**默认配置下 Twitter/X 抓不到热评是平台行为，不是插件故障**。

想要热评和互动数字，请在「消息输出 → 附加内容：热评 → Twitter/X 的 Nitter 实例地址」填入一个可用的 [Nitter](https://github.com/zedeus/nitter) 地址。Nitter 是 X 的开源前端，未登录即可读到回复区与统计数字。

```text
http://127.0.0.1:8585
```

- 支持逗号 / 分号 / 空格分隔多个实例，插件按顺序尝试，前一个失败自动换下一个
- 缺少协议时按 `http://` 补全；末尾斜杠可有可无
- 指向 `localhost`、`127.x`、`10.x`、`192.168.x`、`172.16~31.x` 的自建实例一律直连，不会被「解析走代理」的设置带去绕代理，也不会被媒体下载的公网地址防护拦下（Nitter 地址由你自己填写，属于显式信任；第三方返回的媒体地址仍然只允许公网）
- 单个实例 10 秒超时、整体 18 秒预算，超时即放弃剩余实例，不会拖慢正文解析
- 公共 Nitter 实例普遍不稳定，长期使用建议自建

配置好之后可以额外获得：

- 回复区热评（按点赞数排序，带作者、头像、时间、点赞数）
- 卡片底部的喜欢 / 转发 / 评论 / 阅读统计
- FxTwitter 与 GraphQL 都拿不到作者头像时的头像兜底（自动升级到 `_400x400` 清晰度）

Nitter 抓取成功后就不会再去试 X 公开页（那条路线已经不返回回复数据，白等只会拖慢解析）。只有 Nitter 全部失败或未配置时才回落到 X 公开页，并在失败后按 1 小时冷却给一条 INFO 引导；正文、图片、视频解析不受任何影响。

## 小黑盒热评说明

小黑盒热评只用于能够稳定返回评论结构的 BBS/link 帖子。插件调用 BBS 接口获取首批楼层并整理为统一热评字段，也支持只有正文、没有图片或视频的 BBS 帖子。

游戏详情、商店详情等页面目前不会强行附加热评；如果平台接口没有可靠评论数据，插件宁可不显示，也不会从无关字段拼接或伪造评论。

## ZIP 归档

可在“消息输出 → 导出行为 → ZIP 归档”中设置归档命令。使用方式：

1. 引用一条包含可解析链接的消息。
2. 发送只包含归档命令的消息。
3. 插件生成 ZIP，并写入解析摘要、结构化详情和已成功下载的媒体。

Nova 版本的归档根目录为 `media_parser_nova/`，不会与原插件的归档目录混用。归档总大小可配置，无法下载的媒体会在 `metadata.txt` 中保留原链接和失败原因。

## 安全与隐私

- Cookie、请求头、Token 和本地文件路径不会写入 ZIP 的公开详情字段
- 媒体请求默认使用公网地址校验，避免误访问本地或内网地址
- 下载失败不会静默伪装成成功，摘要会显示跳过或失败原因
- 解析频率限制可以按链接和用户分别配置
- 请遵守目标平台的服务条款、版权要求和当地法律法规
